Shell Interface 알고리즘 재설계

기술 스택
C++MFC
분야
문제 해결
한 줄 요약
절점 분리 로직을 BFS와 비트마스크로 재설계해 15분 이상 소요되던 Shell Interface 생성을 9초 이내로 단축
핵심 역량
엔지니어링 솔루션

왜 이 작업이 필요했나?

지금은 DevOps 업무를 하고 있지만, 2020년부터 2021년까지는 구조해석 소프트웨어(CAE)를 개발했습니다. CAE는 구조물에 하중이 작용할 때 어떻게 거동하는지를 컴퓨터로 미리 계산해 보는 분야인데, 제가 개발한 것은 건설, 토목, 기계 분야에서 사용하는 구조해석 솔루션이었고 Windows 환경에서 C++와 MFC로 개발하는 프로그램이었습니다. 이 글은 당시 담당했던 기능 중 하나인 Shell Interface의 알고리즘을 재설계한 사례입니다.

구조해석 프로그램은 모델을 절점과 요소로 분할해 계산하는데, Shell Interface는 Shell 요소 사이의 인터페이스를 자동으로 생성하는 기능입니다. 그런데 이 기능에 두 가지 문제가 있었습니다. 하나는 속도였습니다. 모델 구조가 복잡할수록 생성 시간이 수 분에서 수십 분까지 증가했습니다. 다른 하나는 정확도였는데, 특정 조건에서 절점 분리가 정상적으로 이루어지지 않아 해석 자체가 실패하는 경우가 있었습니다.

기존 코드에도 개선할 부분이 많았습니다. 입력 검사 단계(CheckInput)에 중복 처리가 많아 필터링이 비효율적이었고, 모델 구조에 따라 결과가 일관되지 않아 다른 모델군으로 확장해 적용하기도 어려운 상태였습니다. 같은 기능인데도 어떤 모델에서는 정상 동작하고 어떤 모델에서는 실패하는 상황이었던 셈입니다. 저는 CAE 개발자로서 이 기능의 알고리즘 개선과 처리 로직 리팩토링을 담당했습니다.

어떻게 해결했나

속도와 정확도는 별개의 문제처럼 보였지만, 저는 둘 다 절점을 분류하고 분리하는 방식에서 기인한다고 판단했습니다. 속도 저하와 결과 오류가 같은 지점에서 비롯된다면, 절점을 분리하는 방식을 변경했을 때 두 문제가 함께 해결될 수 있습니다. 그래서 기존 알고리즘을 부분적으로 수정하는 대신 처리 구조를 재설계했습니다.

절점 분리는 연결 관계를 그래프로 모델링하고 BFS로 탐색하는 방식으로 전환했습니다. 연결된 요소를 순차적으로 탐색하면서 각 절점이 어떤 요소 그룹에 속하는지를 비트마스크로 기록해 두면, 절점의 분리 여부를 판단할 때 조건을 개별적으로 비교하는 대신 비트 연산으로 처리할 수 있습니다. 판단 속도가 향상되는 것은 물론이고, 모든 절점에 동일한 규칙을 적용하므로 결과도 일관되게 도출됩니다.

이에 맞춰 그룹핑 기준도 재정립했습니다. 조건별로 절점을 분류하는 기준을 새로 정리해서, 특정 모델 구조에만 적용되던 처리를 일반화했습니다. 입력 검사 단계는 구조를 단순화하고 중복 절점을 처리할 때 필터링 조건을 강화해서, 불필요하게 반복되던 처리를 제거했습니다.

구현하면서 중점을 둔 부분

비트마스크는 여러 개의 참/거짓 값을 정수 하나의 비트로 집약해 표현하는 기법이므로, 소속 그룹을 비교할 때도 AND나 OR 같은 비트 연산 한 번으로 충분합니다. 그래서 절점마다 소속 그룹을 비트로 기록해 두고, 해당 절점의 분리 여부도 그 연산 한 번으로 즉시 판단하도록 했습니다. 기존 방식에서 분리에 실패하던 조건도 이 규칙 안에서 동일하게 처리되므로, 속도와 정확도를 동시에 확보할 수 있었습니다.

처리 루프도 재검토했습니다. 절점이 많은 모델일수록 루프 안의 개별 비교가 그대로 누적되기 때문에, 필수적인 비교 연산만 남겨 모델 규모가 커져도 처리 시간이 급격히 증가하지 않도록 했습니다.

검증은 실제로 사용 중인 실무 모델 7개 이상으로 진행했습니다. 이 모델들에서 결과가 정상적으로 도출되는 것을 모델별로 확인한 뒤에야 개선 내용을 제품 릴리스에 포함했습니다.

결과

15분 이상 소요되던 Shell Interface 생성이 9초 이내로 단축됐습니다. 장시간 대기해야 하던 작업이 거의 즉시 완료되는 작업으로 전환된 셈입니다. 절점 분리 정확도가 높아지면서 해석 오류가 발생하는 경우도 감소했고, 개선한 기능은 신규 제품 버전에 포함되어 배포됐습니다.

돌아보며

루프를 최적화한 것보다 절점 사이의 관계를 어떻게 표현하느냐가 더 큰 차이를 만들었습니다. 표현 방식을 비트마스크로 전환하자 속도와 정확도가 함께 향상됐습니다.

기술 스택: C++, MFC, BFS 그래프 탐색, 비트마스킹
